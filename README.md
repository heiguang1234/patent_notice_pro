# 专利审查意见通知书助手

本地运行的前后端分离应用。上传申请文件与对比文件，通过 CLIProxyAPI 等 OpenAI 兼容反代生成带引用的通知书草稿。草稿需人工核对事实、引用和结论。

## 目录结构

```text
frontend/                 独立静态前端
  index.html              页面结构
  styles.css              页面样式
  app.js                  上传、API 请求、结果展示和导出
  config.js               后端地址（不放密钥）
backend/                  Python 后端
  main.py                 FastAPI 路由和跨域配置
  config.py               环境配置和文本长度限制
  services/
    documents.py          PDF、DOCX、文本提取及引用编号
    model_client.py       CLIProxyAPI 模型请求和响应解析
    drafting.py           通知书生成流程
    prompts.py            生成规则与提示词
    validation.py         直接引用的逐字匹配检查
    formatting.py         中文标点及纯文本排版
  requirements.txt        后端依赖
.venv/                    项目专用 Python 环境
.env                      本地私密配置（不提交）
app.py                    后端启动入口
start-backend.cmd          Windows 后端启动入口
start-frontend.cmd         Windows 前端启动入口
start-backend.ps1          可选 PowerShell 启动入口
start-frontend.ps1         可选 PowerShell 启动入口
```

## 环境与启动

推荐 Python 3.12。本项目已创建 `.venv`，使用其 Python 可避免影响全局环境。新机器初始化：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`backend/requirements.lock.txt` 记录了本次验证通过的完整依赖版本，需要复现环境时可使用 `-r backend/requirements.lock.txt` 安装。VS Code 已配置默认使用项目 `.venv` 解释器。

现有 `.env` 可继续使用。新机器才需要复制 `.env.example`，请勿覆盖已有配置。

在项目根目录打开两个 PowerShell 终端，分别运行：

```powershell
.\start-backend.cmd
```

```powershell
.\start-frontend.cmd
```

`.cmd` 入口不受 PowerShell 的 `.ps1` 执行策略限制。如果之前运行 `.ps1` 提示“在此系统上禁止运行脚本”，改用上述 `.cmd` 命令即可。也可直接执行相应 Python 命令（分别在两个终端中运行）：

```powershell
.\.venv\Scripts\python.exe app.py
.\.venv\Scripts\python.exe -m http.server 5173 --bind 127.0.0.1 --directory frontend
```

两个服务需要在不同终端运行。前端打开 http://127.0.0.1:5173 ，后端接口文档为 http://127.0.0.1:8765/docs 。后端仅提供 API，页面由前端服务提供。

## 配置

根目录 `.env` 由后端读取，系统环境变量优先：

- `API_BASE_URL`：CLIProxyAPI 的 OpenAI 兼容根地址，例如 `http://127.0.0.1:8317/v1`。
- `API_KEY`：反代密钥，按反代要求填写。
- `MODEL`：反代提供的模型 ID。
- `API_TIMEOUT`：模型请求超时秒数，默认 180。
- `PORT`：后端端口，默认 8765。
- `FRONTEND_ORIGINS`：可选，允许的前端来源，默认 `http://127.0.0.1:5173,http://localhost:5173`，多个来源用英文逗号分隔。

修改后端端口时，同时修改 `frontend/config.js` 的 `apiBase`。修改配置后重启后端。密钥只放 `.env`，不放前端。若反代连接外部上游，文件内容会发送到该上游。

## API 与文件限制

- `GET /api/status`：模型配置状态，不返回密钥。
- `POST /api/draft`：multipart/form-data，包含 `application`（申请文件）、`comparison1`（必填）、`comparison2` 至 `comparison10`（按需选填）、`scope`（补充审查要求）。页面默认显示文件1，可用“添加对比文件”“移除最后一项”调整数量。编号由字段固定指定；未上传2时3仍为对比文件3。返回 `draft`、`documents`、`truncated`（兼容字段，当前为空）和 `warnings`（引用核查事项）。
- 支持可复制文本的 PDF、DOCX、TXT、MD；扫描版 PDF 需先 OCR。
- 单文件上限 20 MB；每份最多约 60,000 字符，全部文件合计约 120,000 字符。超出预算停止生成并提示，不截断原文。
- 引用采用 `[申请文件 §N]`、`[对比文件1 §N]` 等，页面可查看模型收到的完整编号原文。
- 上传不保存到项目目录；框架可能临时缓存上传，请求结束关闭清理。

## 写作规则

正文只包含权利要求评述，直接从“1、权利要求1要求保护主题名称，对比文件1（公开号）为最接近的现有技术。”开始，不复制整条权利要求，不添加开场白、文件清单、额外总评或结尾建议。权利要求1按指定三步法模板书写：以对比文件1为起点，明确区别技术特征、实际解决的技术问题、其他对比文件的公开内容和结合启示，再得出有证据支持的结论。从属权利要求按引用关系及附加特征逐项简评，不再写三步法；已公开的内容直接引用，未公开的内容具体说理。

“相当于”采用技术含义对应，不要求对比文件与权利要求措辞完全一致。对比文件引用的是对比文件原文，“相当于”后引用的是权利要求原文；程序分别核查这两类引文，不能把字面不一致直接认定为技术特征未公开。

三步法始终针对本申请权利要求1整体：内部先拆解全部特征并检查各对比文件完整文本中的候选公开，再形成区别特征、技术问题及结合论证，不将说明书额外限制加入权利要求。引用可保留数句或一至两个相关段落及必要上下文，复杂特征按需增加，不要求压缩到最短句段；同时避免无关内容与重复堆砌。非连续原文分开引用，保留逐字核查。

特征比对后另起段写“该权利要求与对比文件1相比，区别技术特征在于：”，再将（1）、（2）等区别特征各自成段，随后独立写技术问题、“对于区别技术特征（1）……”及“至于区别技术特征（2）……”等逐项论述。段落之间空一行，从属项仍采用简评格式。

首个“对比文件1公开了”先引入技术方案主题名称，写作“一种……方法（相当于一种……方法）”，具体步骤放在“并具体公开了以下技术特征”之后。根据每次实际上传的文件数量组织结合理由，不引用未上传文件，不强制把全部文件用于结论。原件段号出处统一为“（参见说明书第【0057—0069】段）”，没有原件段号时如实使用提取段号或页码，不伪造说明书定位。

模型内部使用「」和『』标记直接引文用于逐字核查；最终通知书移除这些标记和额外双引号，不显示 Markdown 语法或方括号来源标记。原文后直接接中文括号“（相当于对应权利要求原文）”，自动删除该括号前紧邻的标点。正文按编号自然段组织，出处写入“参见说明书第……段”等文字，下载格式为纯文本 `.txt`。核查提示在前端单独显示，不写入复制及下载的正文。

后端先核查模型引文是否在相应类别的文件中逐字出现（仅忽略排版空白），再规范最终中文标点。不匹配时在页面提示。该检查不能确认引文一定属于指定权利要求、指定对比文件或语义对应正确，需人工核查；PDF 的文字提取顺序也可能需要与原件核对。正文用中文标点，保留英文技术标识及数字小数点。

没有证据不能强行认定公知常识或套用不具备创造性的结论。未公开的技术特征在所在评述段落内具体说理，避免在正文外添加总评。

## 前端资源

前端使用原生 HTML、CSS、JavaScript，无框架、外部字体、图片或动画依赖。适配桌面与窄屏；长原文只在展开核对区时创建 DOM，生成正文通过 `textContent` 展示，不运行 Markdown 解析或语法高亮。

生成时通过 `POST /api/draft?stream=true` 接收 SSE 进度，显示提交材料、逐文件文本提取、整理输入、模型生成、核查排版和完成阶段，以及已等待时间。模型正文以流式接收时显示已接收字符数，不显示推测的思考步骤、完成百分比或剩余时间；反代只支持非流式响应时，生成阶段仍等待完整正文返回。心跳仅维持连接，不代表模型产生了新进展。原 `POST /api/draft` 的 JSON 接口保持可用。

页面将“（相当于……）”中的对应技术特征加粗展示，支持嵌套中文括号；采用安全 DOM 节点，不执行模型返回的 HTML。复制和 TXT 下载仍为无 Markdown 标记的纯文本。可使用 `node --test test_frontend.cjs` 验证前端的加粗及流式解析。

可运行 `.\.venv\Scripts\python.exe -X utf8 check_notice_format.py`，使用虚构材料测试真实模型的主题名称、技术含义对应、纯文本及引文格式。此命令会发送一次真实模型请求。
